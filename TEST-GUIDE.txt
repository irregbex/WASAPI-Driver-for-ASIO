WASAPI Driver for ASIO 0.9.8 (public beta) - Test guide
=======================================================

ASIO is a registered trademark of Steinberg Media Technologies GmbH.

Goal: validate on real Windows hardware what cannot be tested at build time.
Report format: test number + OK/FAILED + (if it failed) what happened.
When done: close the DAW, panel > Status > "Open log" (or open
%APPDATA%\WASAPI Driver for ASIO) and attach log.txt and log-previous.txt to
the report.

Preparation
-----------
P0  Install WASAPI-Driver-for-ASIO-0.9.8-Setup.exe (README section 3).
    OK = it finishes without errors and "WASAPI Driver for ASIO" appears in
    the DAW.

Block H - Automatic test (run first, before the manual blocks)
--------------------------------------------------------------
Since 0.8.3 every test prints an "ASIOTime (<test>):" line; each must say
"null 0, no samplePosition 0, no systemTime 0, bad sampleRate 0", and the
T7 line "ASIOTime over the whole run" must say "invalid fields 0". If not,
the test fails and T7 lists the first 8 invalid callbacks: send that part
of WasapiDriver-test.txt. T6 also prints the rate fresh driver instances
start at (the SampleRate of config.ini).
0.9.8: T11 "Bad host calls" runs right after T1: it calls the driver with
invalid arguments and in the wrong order (no sound) and must say "every
invalid call returned the expected error; driver unchanged"; the tests after
it then show that the driver still plays normally.
H1  Close the DAW. Start menu > WASAPI Driver for ASIO > "WASAPI Driver for
    ASIO Automatic test". Wait ~2 minutes (nothing is heard: it sends
    silence).
    OK = last line "RESULT: PASSED" (it may add ", N warnings": note them).
    SKIPPED tests are not failures (they do not apply to this computer). If
    it says "FAILURES = N", attach WasapiDriver-test.txt (the console shows
    where it was saved).
H2  Repeat H1 with the panel in Exclusive mode (open the panel from the
    DAW, Apply, close the DAW).  OK = PASSED. Switch back to Shared
    afterwards.
H3  (Optional, needs a cable) Connect output 1 -> input 1 of the sound card,
    TURN THE VOLUME DOWN, Start menu > "WASAPI Driver for ASIO Latency test
    (cable)", press Enter when asked.
    OK = T8 PASSED (SKIPPED if input 1 is not physical). Note the median and
    "Difference (measured - reported)". If |difference| > 1 ms, report it
    (pending adjustment, ROADMAP 1.3).

Block A - Basics (Shared)
-------------------------
A1  Panel: Mode Shared, "Low latency in Shared" on, buffer 256 > Apply and
    restart.
    OK = the DAW reopens by itself; the status shows "Shared low latency" or
    "Shared standard"; reasonable latencies (< 30 ms).
A2  Play a project for 5 minutes.
    OK = no dropouts; "Output glitches" = 0.
A3  Raise/lower the Windows volume and mute.
    OK = the level changes; mute silences.
A4  YouTube playing at the same time.  OK = both are heard.
A5  Change the project sample rate 48k -> 44.1k -> 48k.
    OK = it keeps playing at both; no hang.
A6  Buffer 64 > Apply. Play for 2 min.  OK = no dropouts or only a few (note
    "Output glitches"). Back to 256.

Block B - Exclusive
-------------------
B1  Panel: Mode Exclusive > Apply.
    OK = status "Exclusive"; output latency lower than in A1.
B2  Play for 5 min.  OK = no audible dropouts.
B3  Stop and resume playback 10 times in a row.
    OK = it always plays again; the DAW does not reset by itself (this
    failed before 0.2.2).
B4  Windows volume.  OK = the level changes.
B5  YouTube.  OK = YouTube is NOT heard (correct in Exclusive mode).
B6  Back to Shared.

Block C - Inputs
----------------
C1  Panel: Main tab > Input device = microphone. Record 30 s of speech.
    OK = the voice is heard, without clicks.
C2  If the microphone is a different device from the output (USB/HDMI):
    record 5 min of a tone or music through the microphone.
    OK = no clicks; the status shows "Input drift: +-N ppm (correcting)".
C3  Enable ASIO Direct Monitoring in the DAW and monitor the track.
    OK = the voice is heard with little delay; status "Direct monitoring:
    on".

Block D - Loopback
------------------
D1  Panel: Loopback = "Everything except this DAW" > Apply. Create a
    Loopback L/R input bus. Play YouTube and record 1 min in the DAW.
    OK = YouTube is recorded; monitoring the track gives no echo.
D2  Loopback = "All audio of the output device".
    OK = YouTube is recorded and so is the DAW (do not monitor).

Block E - Stability
-------------------
E1  With the DAW playing, unplug and plug back headphones/USB.
    OK = the DAW reopens the driver by itself; it does not crash.
E2  Same as E1 but with the panel open.
    OK = the DAW does not crash (this could crash Cubase before 0.2.2).
E3  Change the default device in Windows with output "(Windows default)".
    OK = the audio moves to the new device.
E4  Open and close the panel 10 times, alternating Apply and Cancel.
    OK = no hangs; the DAW stays in front.
E5  Close the DAW with the panel open.
    OK = the DAW closes normally.
E6  Long session: 1 hour of playback.
    OK = no dropouts; note the status counters at the end.

Block F - Other DAWs (optional)
-------------------------------
F1  Ableton Live: A1, A2, C1.
F2  REAPER: A1, A2, C1.

Block G - Meters, load and diagnostics (0.3.0)
----------------------------------------------
G1  Play a project with the panel open.
    OK = the "Outputs" bars move with the music; the white line holds the
    peak ~1.5 s; unused channels in gray.
G2  Speak into the microphone (input active in the DAW) and, with Loopback
    on, play YouTube.  OK = the "Inputs" bars of the microphone and of
    Loopback L/R move.
G3  Raise the DAW master to +6 dB and play.  OK = the red clip indicator of
    the outputs lights up and stays on after lowering the master. Click the
    meters: OK = it turns off.
G4  "DSP load" during playback.  OK = reasonable values (note now/max).
    Load several heavy plugins: OK = the value rises.
G5  "Reset counters" during playback.
    OK = max load, glitches, timeouts, input counters and clips go back to
    0; the audio does not stop; the DAW does not reset.
G6  Exclusive, buffer 64, play for 2 min and force load (open heavy
    programs, move windows).  OK = if dropouts are heard, "Output glitches"
    increases (before 0.3.0 it stayed at 0 in Exclusive mode). Without
    audible dropouts in 2 min with buffer 256: note the value (should be 0
    or almost 0).
G7  Exclusive: stop and resume 10 times.  OK = "Output glitches" does not
    increase just by starting (no false positives at start).
G8  Start menu > WASAPI Driver for ASIO > WASAPI Driver for ASIO
    Diagnostics.
    OK = a console opens with the report, says where it saved
    WasapiDriver-diagnostics.txt and waits for Enter. The report shows the
    Windows version, the registration "present" in 64-bit and 32-bit with
    "DLL file: exists", the devices with their Exclusive formats, and the
    current config.ini and log.txt.
G9  Uninstall.  OK = the Start menu shortcuts disappear.

Block I - 0.4.0 features
------------------------
I1  Profiles: open the panel. OK = the "Profile" combo lists Studio, Laptop
    and Streaming (new installation or first time).
I2  Select "Laptop" > Apply.  OK = the status shows Shared and
    buffer 256; reopen the panel: the combo shows "Laptop".
I3  Change the buffer to 512 > "Save..." > name "Test" > Save.
    OK = "Test" appears in the combo. Select another profile and then
    "Test": the buffer is 512 again. "Delete" with "Test" selected: it
    disappears.
I4  "Save..." with the name "a[b]" or "x=y".  OK = invalid name warning,
    nothing saved.
I5  Application loopback: play music in Spotify (or the browser). Panel:
    Loopback = "One application only"; the "Application" row appears;
    "Refresh" and select the program > Apply. Record Loopback L/R for 30 s
    with another program playing at the same time (e.g. a video in another
    browser).
    OK = only the selected program is recorded.
I6  Close the selected program and "Apply".  OK = the DAW does
    not crash; Loopback is silent; log.txt says the program is not running.
    Open the program again and "Apply": it is recorded again.
I7  Dither: Exclusive on a 16-bit or 24-bit card (the status shows "int16"
    or "int24"/"int32" in Output). OK = status "Dither: TPDF". Play silence
    (empty project): no new noise must be heard. Uncheck Dither > Apply:
    status "Dither: no".
I8  Sinc resampling: a microphone on another device (as in C2). Resampler
    quality = Sinc > Apply.  OK = status "Resampler: sinc"; the reported
    input latency rises by ~0.3 ms (16 samples at 48 kHz); record 5 min of
    music or a 15 kHz tone through the microphone: no clicks. Note "DSP
    load" with Hermite and with Sinc.
I9  Repeat the automatic test (H1) with Sinc and with an Exclusive profile.
    OK = PASSED.

Block J - Extra devices and routing (beta 0.5.0)
------------------------------------------------
Needs two output devices (e.g. built-in speakers + USB or Bluetooth
headphones) and, for J4, two input devices.
J1  Panel: main output device = A; Extra devices & monitoring tab, "Extra devices": select B under
    Outputs > Apply.  OK = the DAW shows outputs "1:Out L",
    "1:Out R", "2:Out L", "2:Out R"; the status has the line
    "Output 2: B ...".
J2  Route one track to 2:Out L/R and another to 1:Out L/R; play for 10 min.
    OK = both play without clicks; "Output 2" with stable drift (note the
    ppm) and underflow/overflow at 0 (or 1 at start).
J3  With J2 playing, unplug B (USB/Bluetooth).  OK = the DAW reopens the
    driver; A keeps working; the 2:* channels exist but are silent. Plug B
    back: the DAW reopens again and B plays again.
J4  Inputs: select a second microphone under Inputs > Apply.  OK = inputs
    "2:In ..." before Loopback; record 1 min of both at once: no clicks;
    status "Input 2" correcting drift.
J5  Select 4 outputs.  OK = the fourth cannot be selected (beep).
J6  Routing: (if an extra device was just selected without applying, the
    dialog says so and already shows the new channels). "Output
    routing..." on a 2-channel output: Channel 1 <- 2, Channel 2 <- 1 > OK >
    Apply.  OK = left and right swapped. "Identity" > OK > Apply: back to
    normal.
J7  Routing with one channel on "Silence".  OK = that side is silent.
J8  Save a profile with extra devices and routing and "Include devices"
    checked, select another profile and come back.  OK = the selections and
    the routing come back.
J9  Automatic test (H1) with an extra device selected.  OK = PASSED with T9
    PASSED; note the "stop:" line of the log with the counters.
J10 Input alignment: "Align devices" on. Record through the main microphone
    and an extra one at the same time, placed together, a clap or sharp
    knocks (or the metronome through the speakers).  OK = in the DAW the
    transients of both tracks match within ~1 ms (zoom to sample level).
    Note the difference. Repeat with alignment off: the difference must be
    larger.
J11 Output alignment: metronome sent to 1:Out and 2:Out at the same time,
    speakers next to each other.  OK = a single click is heard (not a
    double one). Turn alignment off: a double click is heard (the extra
    device later). Status: "Alignment" and "own latency" lines with
    reasonable values.

    right; tabs Main / Advanced / Devices / Status / About.  OK = every

L10 Profiles: with Input device = (None - no inputs) and an output selected, select the profile
    "Laptop" > Apply.  OK = output and input do NOT change. "Save..." a new

Block M - 0.7.0 features
------------------------
[IFACE] = needs an audio interface with inputs and outputs on the same device
(e.g. a USB audio interface with 2 inputs and 2 outputs); [CABLE] = needs a cable from output 1 to input 1;
[2DEV] = needs a second device (USB microphone, headset). Note for Cubase:
Cubase may stop the audio by itself while its own Studio Setup dialog is
open; for M1-M4 open the panel from the monitor window (M5) instead.
M1  Live settings: play a project. In the panel change Gain to -6 dB >
    Apply.  OK = the level drops at once, the audio never stops, the bottom
    bar says "Applied live.", the DAW does not restart the driver (no
    "reset" line in log.txt). Repeat with Dither and with Output routing
    (swap L/R): same result.
M2  Reset settings: change the Buffer (marked with a dot) > Apply.  OK = the
    bottom bar says "The DAW will restart the driver."; the DAW reopens the
    driver by itself within ~2 s; the panel stays open and usable; the
    status shows the new buffer.
M3  Close without Apply: change Gain, press Close, reopen the panel.  OK =
    the old value is shown and nothing changed.
M4  Panel while playing: open the panel during playback and leave it open
    1 minute.  OK = no dropouts ("Output glitches" stays 0).
M5  Monitor window: Main tab > "Floating monitor window" > Apply.  OK = a
    small dark window appears without taking the focus from the DAW (typing
    in the DAW still works), meters move, DSP load / dropouts / latencies /
    one-line summary are filled. Resize and move it, close the DAW, open it
    again: same size and position. Pin: stays above the DAW. Settings: opens
    the panel while the audio runs. Close: the window disappears and the
    option is off in the panel. Move it to a second monitor with another
    scaling (if available): it rescales, nothing cut off.
M6  Monitor position off-screen: with the window placed on a second
    monitor, close the DAW, disconnect that monitor, open the DAW.  OK = the
    window appears on the main screen (top right).
M7  [CABLE] Latency offset: run "Latency test (cable)", answer y to
    "Save ... as a latency offset?".  OK = config.ini has
    OutputLatencyOffsetMs = the printed value; running the test again shows
    a difference within +-1 ms. Advanced tab shows the offset.
M8  Offset live: with the DAW playing, set Output offset = 100 > Apply.  OK
    = "Applied live."; the DAW shows the latency 100 ms larger (Cubase:
    Studio Setup > the driver's latency values) without a restart, or (if
    the DAW does not support it) restarts the driver once. Set it back to 0.
M9  [IFACE] Direct monitoring from the panel: Extra devices & monitoring tab >
    Direct monitoring: Enabled, Input channels In 1-2, Output channels Out 1-2, Level 0 dB > Apply; speak into the
    microphone with headphones.  OK = you hear yourself without the DAW
    monitoring the track; Level -12 and Pan -100 / +100 change smoothly
    (no clicks, also when pressing Mute and when disabling); the output
    meters move with your voice. Note the latency you feel (not zero).
M10 [IFACE] Loaded DAW: with M9 active, load heavy plugins until DSP load is
    above 100 %.  OK = the monitored voice keeps playing (the program may
    break up, the monitor must not).
M11 [IFACE] ASIO Direct Monitoring in Cubase: enable it in Studio Setup >
    VST Audio System, arm a track with monitoring on.  OK = the input is
    heard, track volume and pan change it smoothly, disarming fades it out.
M12 [2DEV] Monitoring across devices: input = USB microphone, output =
    built-in (drift correction active) > enable direct monitoring.  OK = you
    hear the microphone for 10 minutes without clicks or growing delay.
M13 No input: Main tab > Input device = (None - no inputs) > Apply.  OK = direct monitoring is off (the
    note says "No device input is open"), no error.
M14 Clip safety: Level +6 dB, sing loudly with a hot input gain.  OK = no
    harsh wrap-around distortion on the output (soft limiting), the output
    clip LED may light.
M15 Microphone privacy: Settings > Privacy & security > Microphone > turn
    off "Let desktop apps access your microphone"; run Diagnostics.  OK =
    "VERDICT: desktop apps CANNOT use recording devices"; the panel's Extra
    devices & monitoring tab and the Main tab (under Input device, with "Set
    to None") show the same warning. Turn it back on: "can use".
M16 Crash reports (no crash expected): run Diagnostics.  OK = section
    "Crash reports" says "No crash marker." and "No minidumps." (or lists
    existing ones with sizes and dates, paths shown as %LOCALAPPDATA%).
M17 Safe mode (only if a crash happened): after a crash, open the DAW.  OK
    = the panel and the monitor window show "Recovered from a crash in the
    previous session - safe settings used."; the status shows Shared,
    default output, no input, buffer 512; config.ini still has your
    settings. "Use my settings again": the DAW restarts the driver with
    your settings and the banner disappears.
M18 Automatic test (H1).  OK = PASSED; T2 shows "ASIOTime:
    bufferSwitchTimeInfo N, bufferSwitch 0; null 0, no samplePosition 0, no
    systemTime 0, bad sampleRate 0".
