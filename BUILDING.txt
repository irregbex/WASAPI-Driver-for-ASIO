========================================================

Building (Linux or WSL, cross-compiling)
----------------------------------------
  x64:   sh build.sh          needs g++-mingw-w64-x86-64   -> WasapiDriver64.dll
  ARM64: sh build-arm64.sh    needs pip install ziglang    -> WasapiDriverARM64.dll
  x86:   sh build-x86.sh      needs g++-mingw-w64-i686     -> WasapiDriver32.dll
  Diag:  sh build-diag.sh     needs g++-mingw-w64-x86-64   -> WasapiDriverDiag.exe
  Test:  sh build-test.sh     needs g++-mingw-w64-x86-64   -> WasapiDriverTest.exe
  File prefix: WasapiDriver; product name "WASAPI Driver for ASIO".
  All builds use -Wall -Wextra and must produce 0 warnings from src/.
  0.9.10: the DLL builds first compile the SoX Resampler library
  (third_party/soxr, LGPL-2.1-or-later, see its README-vendored.txt) as C,
  one object per file into obj/soxr64, obj/soxr32 or obj/soxra64:
    third_party/soxr/src/soxr.c, third_party/soxr/data-io-portable.c,
    third_party/soxr/fifo-headroom.c, third_party/soxr/src/dbesi0.c,
    filter.c, fft4g32.c, fft4g64.c, cr.c, cr32.c (all in src/)
  with -O2 -std=gnu99 -DSOXR_LIB -DNDEBUG -Ithird_party/soxr and -w: warnings
  are switched off for these third-party files ONLY (upstream code, kept
  unchanged); src/ keeps -Wall -Wextra and 0 warnings. The C++ sources get
  -Ithird_party/soxr/src (soxr.h). No CMake: third_party/soxr/soxr-config.h
  is the hand-written configuration (plain C engine "cr32", no SIMD, no
  OpenMP). soxr is linked statically; no new DLL is imported (ARM64 adds the
  Universal CRT API sets api-ms-win-crt-environment / -utility, parts of
  Windows).
  Builds use -ffile-prefix-map / -fmacro-prefix-map (no build path is
  embedded) and are stripped (-s).
  Option: WB_FLAGS="-DWB_SHOW_ASIO_LOGO=0" sh build.sh (same for the other
  scripts) builds without the Steinberg ASIO Compatible logo; the default
  (1) embeds and shows it (see TRADEMARKS.txt).
  The mingw "win32" thread model is used (the Ubuntu default), so the DLLs
  need no mingw runtime DLLs; every import is a Windows system DLL.

Installer
  Needs installer/lang_en.nsh, lang_es.nsh, header.bmp, welcome.bmp and
  app.ico (a copy of src/res/app.ico) next to the .nsi.
  makensis -DVERSION=0.9.15 installer/WasapiDriver.nsi (nsis package), with
  the 3 DLLs, WasapiDriverDiag.exe, WasapiDriverTest.exe, LICENSE.txt and
  the documents README.txt, QUICK-START.txt, FAQ.txt, COMPATIBILITY.txt,
  TEST-GUIDE.txt, COPYRIGHT.txt,
  THIRD-PARTY-NOTICES.txt, TRADEMARKS.txt, DISCLAIMER.txt, PRIVACY.txt,
  SECURITY.txt and CONTRIBUTING.txt in the parent folder of installer/
  (NOTICES.txt goes next to the .nsi). 0.9.8: also TRACING.txt in that folder
  and trace/WasapiDriver.wprp, "trace/Start trace.bat" and
  "trace/Stop trace.bat" below it (installed into <program folder>\Tracing). Produces
  WASAPI-Driver-for-ASIO-<version>-Setup.exe in that parent folder.
  Optional: -DSIGN_CMD="sh <repo>/scripts/sign.sh" signs the Setup and its
  uninstaller (!finalize / !uninstfinalize); see SIGNING.txt.
  0.9.9: if WasapiDriverARM64X.dll is in that parent folder too, the Setup
  contains it and registers it on Windows on Arm (one registration, no
  question); makensis prints which kind of package it builds. -DARM64X=1
  requires the file, -DARM64X=0 builds without it even if it is there.
  Without the file the Setup is the same as in 0.9.8.

ARM64X (0.8.0 experimental; built at every push and packaged since 0.9.9)
  One DLL with native ARM64 and ARM64EC code. Needs MSVC (cl /arm64EC and
  link /machine:arm64x); the Linux toolchains cannot produce ARM64EC code.
  Built by scripts/build-arm64x.ps1 in the "arm64x" job of
  .github/workflows/build.yml and release.yml on a Windows 11 ARM64 runner
  (by hand: a "Developer PowerShell" for arm64 of Visual Studio 2022 with
  the ARM64 and ARM64EC build tools, from the source root:
  pwsh scripts\build-arm64x.ps1). The script checks the image with dumpbin
  (ARM64X machine, the four exports, no Visual C++ runtime DLL) and ends
  with a ::notice annotation. See ARCHITECTURE.txt section 59.
  0.9.10: the script also compiles the soxr C files with cl /TC /W0 for both
  halves (obj\a64\soxr_*.obj, obj\ec\soxr_*.obj); /W0 applies to those
  third-party files only, the C++ sources keep /W3.

Offline tests (Linux, plain g++)
  0.9.8: sh tests/run_all.sh builds and runs ALL of them (18) and prints a
  summary; exit code 0 only if every test passed. CI (build.yml) runs it, and
  release.yml runs it in a "tests" job that every other job depends on: no
  release is built unless all tests pass. Run it before every release.
  New in 0.9.8 (built with -fsanitize=address,undefined
  -fno-sanitize-recover=all -D_GLIBCXX_ASSERTIONS; SAN=0 sh tests/run_all.sh
  without the sanitizer libraries):
    fuzz_test       deterministic fuzzing of every parser of untrusted data
                    (src/parse.h, update.h, privacy.h, chnames.h, tlg.h);
                    optional argument: iteration multiplier
    asiocheck_test  host argument validation and call order (src/asiocheck.h)
                    with 200000 random host calls
    trace_test      TraceLogging encoder and provider GUID (src/tlg.h, trace.h)
  Single test by hand:
  g++ -O2 -std=c++17 -Wall -Wextra tests/<name>.cpp -o t && ./t
  for resampler_test, sink_test, dmix_test, limiter_test, chnames_test,
  visuals_test (add -D_GLIBCXX_ASSERTIONS: bounds-checked; --dump <folder>
  writes preview images), timeinfo_test (-pthread), strings_test,
  themes_test, update_test (from the source root: 0.9.10 reads
  src/common.h), registry_test (-pthread), icon_test (from the source
  root), ratepolicy_test (0.9.5);
  fixedratio_test (0.9.4; about 90 s since 0.9.10) needs the soxr objects:
    for f in <the nine soxr C files above>; do
      gcc -O2 -w -DSOXR_LIB -DNDEBUG -Ithird_party/soxr -c $f -o obj/$(basename $f .c).o; done
    g++ -O2 -std=c++17 -Ithird_party/soxr/src tests/fixedratio_test.cpp obj/*.o -o ft && ./ft
  (tests/run_all.sh does exactly this and adds -DWB_COUNT_ALLOC=1
  -Wl,--wrap=malloc -Wl,--wrap=calloc -Wl,--wrap=realloc, which lets the test
  count soxr's allocations on the audio-thread path);
  live_test also needs -pthread. Exit code 0 = passed (most also print
  RESULT: PASSED or FAILED).

Offline tests (Linux, no Windows needed)
  sh tests/run_all.sh                      all 18 tests (0.9.8)

  g++ -O2 -std=c++17 -pthread tests/live_test.cpp -o lt && ./lt

CI
  .github/workflows/build.yml (GitHub Actions, ubuntu-24.04 since 0.9.10) builds the
  three DLLs and both tools, runs every offline test (tests/run_all.sh) and
  builds the installer. release.yml builds nothing until its "tests" job
  (the same script) has passed. 0.9.9: both workflows also run the
  "arm64x" job (MSVC, Windows 11 ARM64 runner); the installer job runs
  after it and includes its DLL only when that job passed every check.

Toolchain details
  C++17. DLL libraries: ole32 uuid avrt winmm shell32 user32 advapi32 gdi32
  (0.9.8: ETW functions EventRegister / EventUnregister / EventWriteTransfer
  come from advapi32; EventSetInformation is resolved at run time because the
  32-bit mingw import library lacks it). DLL sources: dll.cpp driver.cpp
  config.cpp panel.cpp crash.cpp update.cpp trace.cpp, plus (0.9.10) the
  nine soxr C files listed above.
  Diagnostics libraries: ole32 uuid avrt advapi32 shell32 user32 (-municode,
  wmain; user32 since 0.9.3 for the console icon).
  Test libraries: ole32 uuid advapi32 shell32 user32 (-municode, wmain);
  the test tool also compiles src/config.cpp (it saves latency offsets with
  the driver's own config writer).
  dbghelp.dll is never linked: the driver loads it at runtime (crash.cpp).
  Resources (src/WasapiDriver.rc): windres for x86/x64, zig rc for ARM64.

Source files
------------
src/common.h          Shared declarations: version (WB_VERSION_*), names
                      (WB_NAME_W, WB_OLDNAME_W, WB_FILEBASE_W), Config,
                      LoopbackMode / DriftMode / ResamplerQ, configuration,
                      profile and log API.
src/config.cpp        config.ini (UTF-16LE) load/save, profiles
                      ([Profile:name], engine-only or with devices), factory
                      profiles, migrations (old settings folder, old profile
                      sections), diagnostic log with rotation.
src/driver.h          WasapiBridge class (IASIO implementation) and its
                      helpers: MultiFifo, InputSource, OutputSink,
                      VolumeCallback, DeviceNotifier, StatusInfo,
                      MeterSnapshot, reset reasons.
src/driver.cpp        The engine: hidden message window (asioMessage
                      marshalling), device resolution, WASAPI stream
                      opening, the real-time audio thread, resampling and
                      drift correction, extra devices, alignment, routing,
                      monitoring, process loopback, meters and DSP load.
src/drift.h           PI drift controller (PiUpdate) and sink write plan
                      (SinkFramesToWrite, SinkTargetPad, SinkSetpoint);
                      used by driver.cpp and tests/sink_test.cpp.
src/sinc.h            Polyphase sinc table (Kaiser) and interpolated
                      coefficients; used by driver.cpp and
                      tests/resampler_test.cpp.
src/appdir.h          Per-user settings folder with its fallback chain
                      (AppData, LocalAppData, TEMP), shared by config.cpp
                      and diag.cpp (0.9.6).

                      names in printed text) and ShortHash (FNV-1a hash of
                      device Ids); used by the DLL, diag and test tools.
src/live.h            SeqPublished<T>: lock-free publication of the LIVE
                      settings from the host thread to the audio thread.
src/dmix.h            Direct-monitoring mixer primitives (ramps, pan law,
                      soft clipper, denormal flush).
src/limiter.h         Hearing-safety output limiter (0.8.0).
src/chnames.h         ASIO channel-name rules (short device name, speaker
                      position, 31 characters, unique; 0.8.0).
src/visuals.h         Panel background renderer (plasma, starfield, copper,

Repository owner (0.9.7)
------------------------
Until the project's GitHub account is filled in, the update source
(WB_UPDATE_REPO in src/common.h), the documents' links, the issue chooser
and the winget manifests use an owner token whose name contains the word
PLACEHOLDER. Builds made that way are safe: upd::IsPlaceholderRepo treats
such an owner as "not configured", so the update check sends nothing. See
RELEASING.txt step 0 for the substitution; rebuild afterwards.

Internal names
--------------
The C++ class is still called WasapiBridge, the window classes are
WasapiBridgeMsg / WasapiBridgePanel / WasapiBridgeMeter / WasapiBridgeName /
WasapiBridgeRoute / WasapiBridgeMonitor / WasapiBridgeTray (WasapiBridgeTestHost in the test tool) and the export
file is WasapiBridge.def. These names are never shown to users and are kept
to avoid needless churn; the product name is "WASAPI Driver for ASIO".
