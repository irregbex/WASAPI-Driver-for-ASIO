WASAPI Driver for ASIO(R) 0.9.14 - Frequently asked questions
=============================================================
ASIO is a registered trademark of Steinberg Media Technologies GmbH.
See also QUICK-START.txt and README.txt (section numbers below).

1. My input / microphone records silence, or the panel says "Input blocked
   by Windows privacy settings".
   Windows denies microphone access to desktop programs. Settings > Privacy
   & security > Microphone: turn on "Microphone access" and "Let desktop
   apps access your microphone", then restart the DAW's audio engine. If you
   do not need inputs, choose Input device = "(None - no inputs)" (the
   "Set to None" button does it). README section 18.

2. Bluetooth: why is there so much delay, and why are my recordings late?
   Bluetooth adds 100-250 ms that Windows does not report, so the DAW cannot
   compensate by itself. Use buffer 512 or more ("Use recommended"), and set
   Advanced > Latency offsets > Output to about +150 ms, then fine-tune
   until a recorded click lines up. Bluetooth is for listening and mixing,
   not for playing live through the computer. Keep "Protect A2DP" on, or the
   headset drops to telephone quality. README section 26.

3. 44.1 kHz or 48 kHz? What is the "low-latency path"?
   Since 0.9.4 low latency works at any rate. In Shared mode Windows mixes
   at the rate set in Sound settings > device > Format (usually 48 kHz).
   With "Low latency in Shared" on, the driver always opens the device at
   that rate with its shortest engine period (IAudioClient3); if the
   project uses another rate (e.g. 44.1 kHz), the driver converts
   internally with an exact fixed ratio (sinc quality by default, no
   drift, latency included in what the DAW is told; 0.9.10: soxr can be
   chosen, see question 20). So keep your project at 44.1 kHz if you like;
   48 kHz on both sides only saves the conversion (a little CPU and its
   latency: about 1.5 ms with sinc, 9.7 ms with soxr). Status shows
   "Engine: ... internal rate conversion 44100->48000 Hz (sinc)" or "no
   conversion". How low it goes
   depends on the device: WasapiDriverDiag.exe tells whether it offers a
   period below the default 10 ms. Exclusive mode uses the project rate
   directly if the device supports it. README sections 10, 29 and 41.

4. No sound after changing a setting or switching driver in the DAW.
   Many DAWs reset their output routing when the driver restarts. Check the
   DAW's routing: Cubase Studio > Audio Connections (F4) outputs; Live
   Preferences > Audio > Output Config; REAPER track/master outputs; FL
   Studio Mixer > master output. Also check Status tab > Output and that
   the Windows device is not muted.

5. The driver is not listed in my DAW.
   Make sure the Setup finished (or install.bat ran as administrator). Both
   64-bit and 32-bit drivers are registered: a 32-bit DAW sees the 32-bit
   one. On Windows on ARM only one 64-bit kind is registered: run the
   Setup again and answer Yes for a native ARM64 DAW, No for an x64 DAW.
   Then run Diagnostics: it shows the registration of both views.

6. Exclusive mode says "busy" or the Status tab shows Shared.
   Another program holds the device exclusively, or exclusive control is
   not allowed. Close other audio programs; in Sound settings > device >
   Advanced (or Control Panel > Sound > device > Properties > Advanced)
   enable "Allow applications to take exclusive control of this device".
   If Exclusive cannot open, the driver falls back to Shared by itself.

7. The DAW crashed. What is safe mode?
   If the driver itself crashes, it writes a crash report and starts the
   next session in safe mode (Shared, default output, no input, buffer
   512); the panel shows a banner and "Use my settings again". If the DAW
   keeps crashing, choose Shared mode and a larger buffer, and send a
   report (question 9). README section 25.

8. Crackles or dropouts.
   Raise the buffer one step (256, then 512); try Exclusive; close heavy
   programs; check "DSP load" and "Output glitches" in the panel. LatencyMon
   shows system drivers that block the CPU. README section 18.

9. How do I send a useful report?
   (a) Panel > Status > "Copy status" and paste it; (b) Start menu >
   Diagnostics: attach WasapiDriver-diagnostics.txt; (c) log.txt and
   log-previous.txt (Status > "Open log"); (d) for stability problems, the
   soak test report WasapiDriver-soak.txt (Start menu > Soak test); (e) your
   line of COMPATIBILITY.txt. These reports mask your user name, computer
   name and user folders, but still contain device names. A crash minidump
   (.dmp) contains process memory: send it only privately. PRIVACY.txt.

10. Does the driver connect to the internet? What does the update check
    send?
    Nothing by default. Only if you click Interface > "Check for updates
    now", or turn on the weekly check, does it make one HTTPS request to
    GitHub (api.github.com) with the header "User-Agent:
    WASAPI-Driver-for-ASIO/<version>": no identifier, no settings, no
    device names, no usage data. Downloads happen only when you click
    Download, come only from GitHub's servers, and are checked (SHA-256,
    digital signature if present) before you can install them; nothing is
    installed without your confirmation. PRIVACY.txt, README section 35.
    The project and its releases are at
    https://github.com/irregbex/WASAPI-Driver-for-ASIO.

11. Which features are stable and which are beta?
    README section 36 (also on the panel's About tab). Beta: extra devices,
    "Follow Windows" sample rate, the Arm64X DLL (Windows on Arm, not yet
    tested on real hardware), the update check.

12. Can I use it with a screen reader or without a mouse?
    Yes: README section 37 (Narrator, keyboard shortcuts, high contrast).

13. What does this setting do? Can I turn the help tips off?
    Rest the mouse on it, or select it with Tab and press F1: a tip
    explains it and says whether it applies live or makes the DAW restart
    the driver. Interface tab > "Show help tips" turns the hover tips off
    (F1 still works). README section 39.

14. Windows audio (YouTube, screen recording) stops when DaVinci Resolve
    starts.
    Resolve probes other ASIO drivers at startup. An exclusive-mode driver
    (e.g. "Generic Low Latency ASIO Driver") takes the device and Windows
    invalidates every shared stream on it. Uninstall that driver if you do
    not need it and select WASAPI Driver for ASIO in Resolve > Preferences >
    System > Audio I/O. KNOWN-ISSUES.txt KI-1.
    Note (0.9.11): current DaVinci Resolve versions offer I/O Engine =
    "System Audio" in Preferences > System > Audio I/O (Windows audio
    directly, with its own buffer size and input/output device lists).
    With that engine Resolve needs no ASIO driver at all, and the problem
    above does not occur. Choose this driver in Resolve only if you want
    ASIO there (for example to share one driver and one setup with Cubase).

15. Cubase runs, the transport moves, but there is no sound and the
    driver's meters do not move.
    After switching ASIO drivers Cubase can leave the outputs "Not
    Connected". Studio > Audio Connections (F4) > Outputs > Stereo Out >
    Device Port: choose "Out L" / "Out R". KNOWN-ISSUES.txt KI-7.

16. Setup (or the uninstaller) says a file is in use and asks me to close my
    audio programs.
    A program still has the driver loaded, so Windows does not let Setup
    replace the DLL (since 0.9.6 Setup checks this first instead of failing
    halfway). Close Cubase, DaVinci Resolve, Ableton Live and any other
    audio program, then click Retry. If it keeps saying so, a closed
    program may still be running in the background: Task Manager > select
    it > End task, then Retry. Cancel stops Setup without changing the
    installed version. KNOWN-ISSUES.txt KI-2.

17. The developers asked me for a "trace". What is it and is it safe?
    A recording of what the driver did (0.9.8), made with a tool built into
    Windows. Run "Start trace" (Start menu > WASAPI Driver for ASIO, or
    Tools in the release folder), reproduce the problem, run "Stop trace",
    and attach the zipped .etl file from C:\Users\Public\Documents\WASAPI Driver
    for ASIO\Traces (it opens in Explorer) to your issue. It
    contains no audio and no file paths; user and computer names are masked
    in the driver's events. Nothing is recorded unless you start it.
    TRACING.txt explains what is in it.

18. Does it work on Windows on Arm (Snapdragon X and other ARM64 PCs)?
    Yes, as a beta. Since 0.9.9 the Setup installs one Arm64X DLL there and
    registers it once, without asking: native ARM64 DAWs and x64 DAWs
    running under emulation both use it (each loads its own half of the
    file; the x64 DAW gets native-speed driver code). 32-bit DAWs use the
    x86 DLL as everywhere. The Arm64X DLL is built and checked automatically
    and a user confirmed it with native ARM64 Cubase on a Snapdragon X Plus
    laptop; emulated x64 DAWs are not reported yet (KNOWN-ISSUES.txt
    KI-9): reports are very welcome (TEST-GUIDE.txt block Z). If a release
    says it was built without the Arm64X DLL, the Setup asks instead
    whether your DAW is native ARM64 or x64, as in 0.9.8 (only that kind of
    DAW sees the driver then).

19. How is this different from Steinberg's generic drivers?
    Steinberg ships two: the old "Generic Low Latency ASIO Driver" (no longer
    developed) and the current "Steinberg built-in ASIO Driver". Built-in
    versions: 1.0.7 (July 2023), 1.0.8 (24 October 2024, Windows 11 on Arm
    preview), 1.0.9 (18 December 2024, file version 1.0.9.26), the latest as
    of October 2026. Its control panel still shows the OLD name in Spanish
    ("Controlador Generico ASIO de Baja Latencia"), French ("Pilote ASIO
    generique a faible Latence"), Italian ("Driver ASIO generico a bassa
    latenza") and Japanese; English and German show the new name. Check the
    version in the title: 1.0.9.x = built-in. In our tests:
      - The old Generic driver opens the device exclusively: other apps go
        silent (KNOWN-ISSUES.txt KI-1).
      - The built-in driver is shared (other apps keep playing), but only on
        devices you tick in its port list: it does not follow the Windows
        default output, Bluetooth headphones must already be connected when
        you select them, and after they disconnect the selection is lost and
        must be set again.
      - This driver is shared by default (Exclusive optional), can follow the
        Windows default output ("(Windows default)"), moves to the next device
        when headphones disconnect and comes back by itself.
    Full table: README.txt, "WHY USE IT". If a Steinberg driver works for you,
    there is no need to switch.

20. Which "Rate conversion" should I choose (soxr, Sinc, Hermite)? (0.9.10)
    It only matters when the project rate differs from the Windows rate of
    the device (e.g. 44.1 kHz project, 48 kHz device) with "Low latency" on.
    Auto (Sinc, low latency) = the default and the 0.9.9 converter: very
    clean (about 115 dB signal-to-noise), 1.5 ms of look-ahead; "Sinc (low
    latency)" is the same. soxr (best quality, +8-10 ms) = the SoX
    Resampler library (Steinberg's built-in driver installs a soxr.dll too):
    the cleanest result (about 132 dB, no aliasing), but about 8-10 ms more
    latency per direction at 44.1-192 kHz, more at 16-32 kHz. Hermite (light) = least CPU and latency, audibly less
    clean on high frequencies; only used when the rate goes up. Mixing and
    listening: soxr. Playing a software instrument or monitoring through the
    DAW at that rate: Auto or Sinc, or set Windows and the project to the same rate
    and no conversion is needed at all. The DAW is told the exact latency in
    every case (README section 41, KNOWN-ISSUES.txt KI-10).

21. The panel says Exclusive but the status says Shared. Why? (0.9.11)
    The driver tried Exclusive mode at the project's rate and the device
    refused every format, so it fell back to Shared mode (which works at
    any rate). Since 0.9.11 the status line says so: "Active mode: Shared
    ... (Exclusive not available at 44100 Hz; the device is fixed at
    48000 Hz by its own driver or the Windows default format)", and the
    panel's bottom bar shows "Exclusive not available, running Shared".
    The usual reason is a device whose own driver fixes the rate: in
    Windows > Settings > System > Sound > the device > Properties, the
    "Default format" is greyed out at another rate. What to do: set the
    device to the project's rate in the manufacturer's control panel (for
    example "Yamaha Steinberg USB Driver" in the Control Panel for a
    Steinberg UR interface, once that driver is installed), or change the
    Windows default format when it is not greyed out, or set the project
    to the device's rate. Shared mode is fine for most work; Exclusive
    only saves a few milliseconds. KNOWN-ISSUES.txt KI-12.
    0.9.12: the same note can appear when the device accepted Exclusive
    for the OUTPUT but the event-driven Exclusive capture of the INPUT
    could not be set up (rare: "Exclusive input not available, input runs
    Shared"); recording then works in Shared mode.

24. Why did my reported input latency grow in 0.9.12? (0.9.12)
    The input FIFO now always keeps one capture period of margin (10 ms
    at 44.1 kHz with the Windows engine) against a late capture packet,
    at every buffer size. 0.9.11 added it only below one period and lost
    input at a 512 buffer (KNOWN-ISSUES.txt KI-11). The DAW compensates
    the reported latency when it places the recording; the monitoring
    delay through the DAW grows by that period (use the panel's direct
    monitoring or the interface's own monitoring for zero-latency
    listening). In Exclusive mode the capture is now event-driven at the
    device's default period (KI-13): the Input line of the status shows
    "[... event-driven, period N]". 0.9.13: N is the smallest multiple of
    the device's default period that holds HALF the ASIO buffer (0.9.12
    took the whole buffer: 882 frames and 63 ms at a 512 buffer; 0.9.13:
    441 frames, about 41 ms), and the capture is taken one period per
    period by a trusted clock ("gated N" at the end of the Capture line
    counts the drains that found no new period: normal, not a problem).
    0.9.14: that clock is the OUTPUT stream's clock when the input is on
    the same device as an Exclusive output (the capture stream's own clock
    of the tested interface driver ran as wrong as its packets); on
    another device the system timer. The log line "stop: input capture
    gate: ... clock=output|qpc" says which one was used.

22. The input level is very low in Shared mode. (0.9.11)
    Shared mode goes through the Windows audio engine, which applies the
    device's input volume: Windows > Settings > System > Sound > Input >
    the device > "Input volume". On a system that never used a microphone
    in Windows it was found at 1 %, which turned a clipping interface
    preamp into -48 dBFS in the driver. Set it to 100 and leave the gain to
    the interface. Also turn off "Audio enhancements" for that device.
    Exclusive mode bypasses this volume. If the level is still low with a
    condenser microphone, check the +48 V switch of the interface.

23. My interface has two inputs but the driver shows one "Line" input.
    (0.9.11)
    Windows exposes the two inputs as one stereo endpoint (input 1 = left,
    input 2 = right); the driver passes it to the DAW as two ASIO input
    channels. Split them in the DAW: Cubase > Studio > Audio Connections >
    Inputs > Add Bus > Mono, one bus per channel. The same applies to the
    manufacturer's own ASIO driver.
