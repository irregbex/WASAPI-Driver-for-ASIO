Change in 0.9.6 that affects the results above (re-test when you can)
  - With Low latency on and a DAW rate below the Windows rate (e.g. 44.1 kHz
    project, 48 kHz device), the internal up-conversion now uses sinc by
    default instead of Hermite (KNOWN-ISSUES.txt KI-5). Output latency grows
    by about 64 input frames (about 1.45 ms at 44.1 kHz); the driver reports
    it to the host, so recordings stay aligned. CPU use of the conversion is
    higher (about 12 M multiply-adds per second for stereo, several times
    Hermite), still small on current CPUs. All converters of one session
    share a budget of 150 M multiply-adds per second.

How to add your result
----------------------
1. Run the Automatic test (Start menu) with the DAW closed, then the
   manual blocks of TEST-GUIDE.txt that apply (at least H, N and R), and
   if you can the Soak test (60 min) with one unplug/replug.
2. Copy one row per host and device into your report, in the same format:
     Host (version, 32/64-bit) | Device (brand, model, connection) |
     Mode / buffer | Status | Notes (sample rate, Windows version, what
     failed, the test number)
3. Attach WasapiDriver-test.txt, WasapiDriver-soak.txt (if run),
   WasapiDriver-diagnostics.txt and "Copy status" (FAQ.txt question 9).
   They mask your user name, computer name and folders.
4. Do not include personal data in the Notes column.
Maintainers merge the reported rows into this table for the next version;
a row becomes "tested OK" only with the test reports attached.
