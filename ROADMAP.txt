-----------------------------------------------
No new features until 1.0 (accepted exceptions: 0.9.2 help tips, 0.9.3
application and tray icons, interface only; 0.9.4 low-latency engine at any
sample rate, suggested by Microsoft's Windows music team; 0.9.8 hardening and diagnostic tracing, requested

the same team, packaging only). Only fixes for defects found on real hardware,
in reviews or by the soak test, and documentation. 1.0 is released when:
- every offline test passes (tests/run_all.sh, enforced by release.yml since 0.9.8);
- TEST-GUIDE.txt blocks A-R, U, V, W, X and Y pass on the configurations of COMPATIBILITY.txt
  marked "tested OK", with no open crash or audio-dropout defect;
- a 60-minute soak test (WasapiDriverTest.exe --soak 60) PASSES with at
  least one unplug/replug and one sleep/resume, in Shared and in Exclusive;
- the beta features (README section 36) are either confirmed on hardware
  and promoted to stable, or stay marked beta in 1.0;
- the project is published (update source configured, signed Setup if a
  certificate is available).

Why not a kernel driver
-----------------------
A kernel driver (WDM/ACX) only beats this design if you control the hardware
(your own interface). For existing sound cards, WASAPI Exclusive reaches the
same DMA buffer of the vendor's driver (WaveRT): the latency difference is
1-2 ms and the risk (blue screens, Microsoft signing) is not worth it.
